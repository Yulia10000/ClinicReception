# Стандарт кодування проєкту ClinicReception

## 1. Загальні положення

Проєкт ClinicReception розробляється мовою C# на платформі .NET 8. Код повинен бути зрозумілим, однорідним та придатним для подальшого розширення. Правила оформлення контролюються засобами .editorconfig, Roslyn та StyleCop.Analyzers.

## 2. Іменування

| Сутність        | Конвенція            | Приклад            | Антиприклад       |
| --------------- | -------------------- | ------------------ | ----------------- |
| Клас            | PascalCase, іменник  | Patient            | patient           |
| Інтерфейс       | I + PascalCase       | IPatientRepository | PatientRepository |
| Метод           | PascalCase, дієслово | CalculateTotal     | calc              |
| Властивість     | PascalCase           | PatientId          | patient_id        |
| Приватне поле   | _ + camelCase        | _items             | items             |
| Локальна змінна | camelCase            | totalAmount        | ta                |
| Константа       | PascalCase           | MaxPatientCount    | MAX_COUNT         |
| Перелічення     | PascalCase           | VisitStatus        | visitstatuses     |

## 3. Форматування

1. Відступ у коді становить 4 пробіли.
2. Використання табуляції для відступів не допускається.
3. Максимальна довжина рядка становить 100 символів.
4. Фігурні дужки оформлюються у стилі Allman.
5. Фігурні дужки використовуються навіть для однієї інструкції.
6. Між членами класу використовується один порожній рядок.
7. Директиви using розташовуються на початку файлу.
8. Невикористані директиви using видаляються.
9. Простори імен записуються у файловому стилі.
10. Кожен файл завершується символом нового рядка.

## 4. Коментарі та документація

Коментарі повинні пояснювати причину прийнятого рішення, а не дублювати очевидний код.

Поганий приклад:

```csharp
// збільшуємо лічильник на одиницю
count = count + 1;
```

Добрий приклад:

```csharp
// Значення зберігається окремо, щоб не змінювати початкові дані пацієнта.
int currentAge = patient.Age;
```

## 5. Структура проєкту

Проєкт поділений на два основні проєкти:

* ClinicReception.Core — логіка предметної області;
* ClinicReception.App — консольний інтерфейс застосунку.

У ClinicReception.Core класи предметної області розміщуються у теці Domain.

## 6. Правила комітів

Для комітів використовується Conventional Commits.

Основні типи:

* feat — додавання функціональності;
* fix — виправлення помилки;
* docs — зміни документації;
* chore — зміни конфігурації та інфраструктури;
* style — зміни форматування.

Повідомлення коміту повинно коротко описувати виконану зміну.
